# Design

## Context

`MobileError` in `hq-mobile` has `Failed { reason }`, `Refused { reason }` and `NotConnected`, with
`#[error]` texts for Rust. UniFFI's generated Kotlin ignores those texts: its `message` is
`"reason=…"` for the two with a field and empty for `NotConnected`.

## Decisions

### D1. One Kotlin function for the owner's text

`MobileException.ownerText()` returns the `reason` of `Failed` and `Refused`, and "Not connected to
the computer." for `NotConnected`. Every screen that shows an error uses it, and a unit test covers
each variant.

Rejected: `#[uniffi(flat_error)]` (it drops the fields, and pairing reads `Refused.reason` to add its
own hint); editing the generated file (it is regenerated by every build).

## Risks

- A new variant added later would need a branch here; the `when` is exhaustive, so the build fails
  until it has one.
